# DynamicCounter 核心功能分析

## 主要目的
`DynamicCounter` 是一个动态计数器系统，允许在运行时注册和查询计数器，支持多个后端同时监听这些计数器。

## 关键设计

### 核心类和结构

**DynamicCounter（主类）**
- 接收一个 `key`（计数器标识）和一个 `Callback`（返回 int64_t 的函数）
- 生命周期管理：构造时注册，析构时注销
- 内部使用 `Guard` 结构体管理资源和生命周期

**Guard（内部守卫类）**
- 执行实际的注册/注销逻辑
- 保存计数器 key、回调函数和所有后端引用
- 非可复制、非可移动（删除了所有复制和移动构造函数）
- 构造时：
  - 检查计数器是否已注册（防止重复注册）
  - 向所有已注册的后端通知新计数器
- 析构时：
  - 通知所有后端注销计数器
  - 从全局注册表中移除

**DynamicCounterBackendIf（后端接口）**
- 抽象基类，定义后端必须实现的接口
- `registerCounter`：当新计数器被创建时调用
- `unregisterCounter`：当计数器被销毁时调用（必须等待所有正在进行的回调完成）

### 全局状态管理

**dynamicCounterBackends()**
- 线程安全的静态全局容器
- 存储所有已注册的后端实现
- 使用 `Synchronized` 进行线程同步

**registeredCounters()**
- 线程安全的静态全局集合
- 追踪所有已注册的计数器名称
- 防止重复注册相同 key 的计数器

## 执行流程

1. 创建 `DynamicCounter` → 触发 `Guard` 构造
2. `Guard` 获取当前所有后端和已注册计数器列表
3. 检查 key 是否已存在（若存在抛异常）
4. 将 key 插入已注册计数器集合
5. 遍历所有后端，调用它们的 `registerCounter` 方法
6. 销毁 `DynamicCounter` → 触发 `Guard` 析构
7. 通知所有后端注销该计数器
8. 从已注册集合中删除该 key

## 线程安全特性

- 使用 `Synchronized` 包装器保护共享数据结构
- `withLock` 方法提供临界区保护
- 后端必须自行实现 `unregisterCounter` 时等待回调完成

---

- **动态监控系统**：支持运行时注册/注销计数器
- **多后端架构**：单个计数器可被多个监控后端同时使用
- **线程安全**：使用 `Synchronized` 保护全局状态
- **防重复注册**：同一 key 只能注册一次，防止冲突
- **回调驱动**：计数器值由用户提供的回调函数动态计算
- **生命周期管理**：通过 RAII 模式自动管理注册和注销
