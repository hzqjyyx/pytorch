# CallOnce.h 文件分析

这个文件实现了一个自定义的 `call_once` 机制，用于替代 `std::call_once` 以避免潜在的死锁问题。

## 核心实现

**call_once 函数**（第16-22行）
- 接收一个 Flag、一个可调用对象 `f` 和可变参数
- 首先快速检查 `flag.test_once()` 是否已初始化
- 如果未初始化，调用 `flag.call_once_slow()` 执行实际初始化

**once_flag 类**（第24-68行）
- 替代 `std::once_flag` 的自定义实现
- 使用 `std::atomic<bool>` 和 `std::mutex` 保证线程安全
- `test_once()` 方法使用内存序 `acquire` 快速检查初始化状态
- `call_once_slow()` 方法在获取互斥锁后再次检查状态，避免重复执行

## 关键特性

- **MSVC 兼容性处理**：在 Windows 上移除 `constexpr` 声明以避免编译错误
- **双重检查锁定**：先用原子操作快速检查，再用互斥锁保证线程安全
- **内存序优化**：使用 `memory_order_acquire` 和 `memory_order_release` 实现轻量级同步
- **不可复制/移动**：删除了拷贝和移动构造/赋值函数

## 主要用途

- 避免 `std::call_once` 的已知死锁问题
- 为单次初始化提供线程安全的保证

---

**核心功能点：**

• 自定义 call_once 实现，替代标准库版本避免死锁
• 使用原子操作和互斥锁实现线程安全的一次性初始化
• 快速路径检查 + 慢速路径执行的双重检查锁定模式
• 支持传递可调用对象和任意参数
• 内存序优化以最小化性能开销
