## ThreadPool 核心功能分析

### 主要类结构

**TaskThreadPoolBase** (线程池基类)
- 定义线程池的抽象接口
- 提供 `defaultNumThreads()` 静态方法计算默认线程数

**ThreadPool** (具体实现)
- 实现任务队列驱动的线程池
- 支持两种任务类型：带线程ID和不带线程ID的任务
- 使用条件变量进行线程同步

**TaskThreadPool** (增强版本)
- 继承自 ThreadPool
- 自动设置线程名称和 NUMA 绑定

### 关键操作流程

**初始化 (constructor)**
- 创建指定数量的工作线程
- 每个线程运行 `main_loop()` 等待任务
- 支持自定义初始化回调函数

**任务提交 (run / runTaskWithID)**
- 将任务添加到队列
- 唤醒一个等待的工作线程
- 标记线程池为未完成状态

**任务执行 (main_loop)**
- 工作线程循环等待任务
- 执行任务时释放互斥锁（防止死锁）
- 完成后更新可用线程计数
- 所有线程可用且队列空时标记为完成

**销毁 (destructor)**
- 设置 running 标志为 false
- 通知所有线程退出
- join 所有线程

### 线程安全机制

- `mutex_`: 保护任务队列和状态变量
- `condition_`: 唤醒等待工作线程
- `completed_`: 通知主线程所有工作完成
- `atomic_bool running_`: 原子操作标志运行状态

### 关键设计细节

**线程数计算优先级**
1. cpuinfo 库：物理核心数 → 逻辑处理器数
2. 标准库：`std::thread::hardware_concurrency()`
3. 默认值：1（无法获取硬件信息时）

**锁管理策略**
- 任务执行时显式释放锁，防止用户代码重入死锁
- 任务析构前释放锁（避免析构函数中可能的重入调用）
- 循环条件检查时持有锁以保证一致性

---

### 核心功能总结

- **线程池管理**：创建、初始化、销毁工作线程
- **任务队列**：FIFO 队列存储待执行任务
- **同步原语**：条件变量实现高效等待/唤醒
- **状态追踪**：可用线程数、完成状态、运行标志
- **异常处理**：捕获任务执行异常并记录日志
- **灵活配置**：支持自定义线程数、NUMA 节点、初始化函数
